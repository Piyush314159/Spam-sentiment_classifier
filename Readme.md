# Spam Classification from Scratch

Multinomial Naive Bayes and logistic regression implemented with NumPy, with custom bag-of-words/TF-IDF and ROC evaluation. No scikit-learn is required.

## Corrected evaluation protocol

The 5,572-message dataset is divided into 3,565 training, 892 validation, and 1,115 test messages. The original 20% test partition is preserved with seed 42; seed 43 reserves 20% of the remaining messages for validation.

- Vocabulary and IDF are fitted on training messages only.
- Logistic-regression early stopping uses validation loss and restores the best validation checkpoint.
- Decision thresholds for both models are selected by validation F1.
- Test labels are used only for final metric calculations, never for threshold selection or early stopping.

The test partition was inspected in earlier experiments. Correcting the pipeline does not make it a newly untouched external holdout; use new independent data to confirm generalization. The previous F1 0.9493 and associated threshold-tuned test results are superseded.

## Run

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python main.py
python -m unittest test_evaluation_integrity -v
```

Outputs: `results/metrics.json`, `results/roc_curve.png`, and `results/loss_curve.png`. `test.py` is a separate existing exploratory script and is unchanged.

## SQL storage and error analysis

The normal workflow uses SQLite at `data/spam.sqlite3`, through Python's built-in
SQLite driver. Messages are read from SQL in their original order. The TSV is an
import source: its fingerprint prevents repeated imports, changed content creates
a new snapshot, and an already imported corpus works if the TSV is absent.
Duplicate messages keep separate positions, preserving the seeded evaluation splits.

Every `python main.py` run saves both models' metrics and all held-out per-message
probabilities and decisions in one transaction. Existing JSON and plot exports
are still produced. Model code, threshold selection, vocabulary fitting and
validation/test boundaries are unchanged. Database errors are reported directly;
there is no storage-off switch or silent fallback.

Query the latest run or inspect its misclassified messages:

```bash
python -m src.database
python -m src.database --errors --model naive_bayes --limit 20
```

Tables: `datasets`, `messages`, `evaluation_runs`, `model_metrics`, `predictions`.
The `classification_errors` SQL view joins predictions back to the actual message
and label. Run IDs retain previous evaluations, and dataset IDs keep predictions
linked to the exact imported data. The generated database is excluded from Git.
